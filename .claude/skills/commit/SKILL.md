# 커밋 스킬 (Commit Skill)

스테이지된 변경사항을 분석하여 **커밋 단위와 메시지를 step by step으로 함께 작성**하고, 사용자 확인 후 **커밋까지 실행**합니다.

## 주의사항

- **절대 `git push`를 실행하지 않습니다.** push는 어떤 상황에서도 금지입니다.
- 커밋 실행 전 반드시 사용자의 최종 확인을 받습니다.

## 작동 방식

1. 스테이지된 변경사항 확인
2. 변경사항 분석
3. 커밋 단위가 크면 **분리 추천을 먼저** 진행
4. 커밋별로 순서대로 제목 → 본문 순으로 질문

## 커밋 메시지 형식
```

{타입}: {제목}

{본문 - 상세 설명}

```

**예시:**
```

feat: 사용자 프로필 수정 기능 추가

- 닉네임 및 프로필 이미지 변경 API 연동
- 수정 성공/실패 시 토스트 메시지 표시
- 변경 전 데이터 초기화 로직 추가

```

## 커밋 타입 기준

타입은 변경사항을 분석하여 자동으로 결정합니다. 사용자에게 묻지 않습니다.

| 타입     | 적용 기준 |
| -------- | --------- |
| feat     | 새로운 기능 추가, 기존 로직 변경 및 개선 |
| fix      | 의도한 동작과 다르게 구현된 버그 수정 |
| refactor | 동작은 동일하나 코드 구조/내부 로직 변경 |
| style    | 로직 변경 없이 포맷, CSS 등 스타일만 변경 |
| docs     | 주석 추가, 오타 수정, 문서 변경 |
| test     | 테스트 코드 추가 및 수정 |
| chore    | 빌드 설정, 패키지, 환경 설정 등 그 외 작업 |

**타입 결정 우선순위**: 변경 목적이 불분명할 경우 `feat > fix > refactor` 순으로 판단합니다.

## 커밋 단위 분리 기준

다음 조건 중 하나라도 해당하면 **분리 추천을 우선**합니다:

1. 변경 파일이 10개 이상인 경우
2. 서로 다른 타입의 변경이 섞여 있는 경우 (예: feat + fix + refactor)
3. 여러 도메인/폴더에 걸친 변경이 있는 경우
4. 커밋 제목을 한 문장으로 설명하기 어려운 경우

## Step by Step 진행 방식

### Step 1. 분리 여부 결정 (분리가 필요한 경우에만)

분리 기준에 해당하면 먼저 분리 추천을 보여주고 사용자에게 확인합니다.
```

:warning: 변경사항이 다양합니다. 커밋을 분리하는 것을 추천합니다.

:file_folder: 분석된 변경사항:

- src/components/ProductFilter.tsx → feat
- src/components/CartItem.tsx → fix
- src/hooks/useFetch.ts → refactor

:bulb: 추천 분리안:
[1] feat: 상품 목록 필터 기능 추가
[2] fix: 장바구니 수량 변경 시 합계 미반영 수정
[3] refactor: 공통 API 호출 로직 훅으로 분리

→ AskUserQuestion: "위 분리안대로 진행할까요, 하나의 커밋으로 합칠까요?"

```

### Step 2. 커밋별 제목 확인

커밋마다 순서대로 진행합니다. AI가 제목을 먼저 제안하고 사용자에게 확인합니다.
```

[1/3] feat 커밋 제목을 작성합니다.

:bulb: 추천 제목: feat: 상품 목록 필터 기능 추가

→ AskUserQuestion: "이 제목으로 진행할까요? 수정하고 싶다면 원하는 제목을 입력해주세요."

```

### Step 3. 커밋별 본문 확인

제목이 확정되면 본문을 추가할지 확인합니다.
```

→ AskUserQuestion: "본문에 추가할 설명이 있나요? (없으면 '없음' 또는 엔터)"

```

- 설명을 입력하면 해당 내용을 본문에 추가합니다.
- 없다고 하면 본문 없이 제목만으로 커밋 메시지를 확정합니다.

### Step 4. 최종 확인 및 커밋 실행

모든 커밋의 제목과 본문이 확정되면 전체 결과를 보여주고 실행 여부를 확인합니다.
```

:package: 최종 커밋 목록:

[1/3] feat: 상품 목록 필터 기능 추가
  파일: src/components/ProductFilter.tsx, src/utils/filterHelpers.ts
  본문: - 카테고리 및 가격 범위 필터 UI 추가 / - 필터 상태 초기화 버튼 추가

[2/3] fix: 장바구니 수량 변경 시 합계 미반영 수정
  파일: src/components/CartItem.tsx

[3/3] refactor: 공통 API 호출 로직 훅으로 분리
  파일: src/hooks/useFetch.ts
  본문: - 중복된 fetch 로직을 useFetch로 통합 / - 로딩/에러 상태 공통 처리

→ AskUserQuestion: "위 내용으로 커밋을 실행할까요?"

```

사용자가 확인하면 각 커밋을 순서대로 실행합니다:

1. `git add`로 해당 커밋에 포함될 파일을 스테이지
2. `git commit`으로 커밋 실행
3. 모든 커밋 완료 후 결과를 출력

```

:white_check_mark: 모든 커밋이 완료되었습니다!

[1/3] feat: 상품 목록 필터 기능 추가 ✓
[2/3] fix: 장바구니 수량 변경 시 합계 미반영 수정 ✓
[3/3] refactor: 공통 API 호출 로직 훅으로 분리 ✓

```

**⚠️ `git push`는 절대 실행하지 않습니다. push가 필요하면 사용자가 직접 실행하세요.**

## 에러 처리

### 스테이지된 변경사항이 없는 경우
```

:x: 스테이지된 변경사항이 없습니다.
먼저 변경사항을 스테이지하세요.

git add <파일명>

# 또는

git add .

```
